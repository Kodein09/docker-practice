## Задача №1: Docker Network Isolation

#### Есть приложение из трёх контейнеров:

    Client
      │
      ▼
    Nginx
      │
      ▼
    Backend
      │
      ▼
    PostgreSQL

Необходимо спроектировать Docker-сети и написать docker-compose.yml, соблюдая следующие требования:
Nginx — единственный контейнер, доступный с хост-машины и извне. Публикуется порт 80.
Backend не должен публиковать свои порты на host, но Nginx должен обращаться к нему по DNS-имени: http://backend:8080

PostgreSQL не должен быть доступен ни с host, ни из внешней сети.
Backend должен подключаться к PostgreSQL по:postgres:5432

Nginx не должен иметь прямого сетевого доступа к PostgreSQL.
PostgreSQL не должен находиться в одной сети с Nginx.
Необходимо использовать минимум две Docker bridge-сети:frontend
backend

Нельзя использовать:network_mode: host
--privileged
публикацию 8080 и 5432 через ports

Ожидаемая топология:

    HOST / INTERNET
           │
         :80
           │
           ▼
     ┌───────────┐
     │   nginx   │
     └─────┬─────┘
           │
    frontend network
           │
           ▼
     ┌───────────┐
     │  backend  │
     └─────┬─────┘
           │
     backend network
           │
           ▼
     ┌───────────┐
     │ postgres  │
     └───────────┘

### Что должен предоставить кандидат:
docker-compose.yml, конфигурацию Nginx для proxy на backend:8080 и кратко объяснить, как Docker DNS позволяет находить 
контейнеры по именам и почему Nginx при такой конфигурации не сможет обратиться к postgres:5432.
